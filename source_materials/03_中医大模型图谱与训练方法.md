# 03 · 中医 TCM 大模型的分类 · 训练方法 · 数据版图

对应江老师提的第（3）点：**目前中医 TCM 大模型的分类、训练类别方法（sft/rl/grpo）、有哪些数据**。

> **使用说明**：本文件给的是**综述骨架 + 我们手上已核实的部分**。表格里凡标 `[待核]` 的格子，都需要莎特老师回到该模型的原始论文/仓库确认后再落笔 —— 中医大模型这一块二手转述的错误率很高（我们自己就踩过：某仓库挂着"仲景"的名字，实际是 Qwen1.5-1.8B 的拷贝，真正的仲景在另一个 HF 账号下）。**凡我们没亲自核过的，宁可留空。**

## 一、建议的分类轴（三条轴，不要只用一条）

综述部分如果只按"模型名字列一排"，很难写出结构。建议按三条正交的轴切：

### 轴一：按**能力形态 / 模态**分

| 类别 | 说明 | 代表（需核实后填全） |
|---|---|---|
| **A. 通用中医对话/问答型** | 纯文本，覆盖理论、辨证、方药，目标是"通科中医" | BianCang 系列、ShizhenGPT-LLM、Sunsimiao、Fu-TCM、Xinghe、TCMChat `[待核]` |
| **B. 医学推理型** | 长 CoT / 慢思考，强调推理链而非知识记忆 | HuatuoGPT-o1 系列 |
| **C. 多模态诊法型** | 舌诊、面诊、脉象信号、体质辨识等，视觉/信号输入 | ShizhenGPT 的多模态版本 `[待核具体模态覆盖]`；舌诊专用模型另有一批 `[待检索]` |
| **D. 中药 / 饮片识别型** | 药材图像识别、真伪鉴别、饮片分类，多为 CV 或视觉-语言 | `[待检索]` —— 江老师点名要的一类，我们手上没有材料 |
| **E. 处方推荐 / 药对挖掘专用型** | 只做方剂推荐这一件事，常与数据挖掘方法混用 | Lingdan 系列（`Lingdan-13B-PR` 的 PR 后缀即处方推荐）`[待核]` |
| **F. 知识图谱 + RAG 平台型** | 模型只是入口，主力是 KG 与检索 | ZhongYan（JBHI）—— **已核实**，见下 |
| **G. 泛医学（非中医专属）但常被拿来对照** | 中西医混合语料，中医只是其中一档 | HuatuoGPT / HuatuoGPT-II、Baichuan-M1、DISC-MedLLM、WiNGPT2、TaiYi、PULSE |

> **写作提示**：江老师特意点了"有些专门做草药识别、多模态舌诊"，说明他想要的是这一轴。D 类和 C 类是我们目前**完全没有材料**的两格，需要莎特老师单独检索补上（建议检索词：TCM tongue diagnosis multimodal LLM / Chinese herbal medicine image recognition / 中药饮片识别 深度学习）。

### 轴二：按**训练阶段组合**分

这一轴最能体现我们的位置。把每个模型拆成用了哪几段：

```
CPT（继续预训练）→ SFT（指令微调）→ 偏好对齐（RLHF / DPO / GRPO / RLVR）→ 推理增强（RAG / KG）
```

| 阶段 | 在中医垂域的典型做法 | 备注 |
|---|---|---|
| **CPT** | 古籍 + 教材 + 期刊灌 B 级 token 量注入领域知识 | ZhongYan：3.9B token / 11.1 GB（1500+ 古籍 2.4B、60+ 教材词典、32k 方药条目、120+ 指南、45k EHR、300+ 论文）—— **已核实** |
| **SFT** | 全参 / LoRA / QLoRA；语料从几万到几十万条 | ZhongYan：272,000+ 条 / 794M token（LoRA）—— **已核实**。**我们：135,797 条，只用这一段** |
| **DPO / RLHF** | 用医师偏好或 KG 一致性做奖励 | ZhongYan 用 DPO + KG 奖励 —— **已核实** |
| **GRPO / RLVR** | 中医任务里 MSDD（准确率）、PR（Jaccard/F1）、ED（选择题）**都可程序验证**，是理想的 RLVR 场景 | HuatuoGPT-o1 走的是 verifier + RL 路线 `[待核具体算法是 PPO 还是 GRPO]`。**我们没做，但这是 Future Work 里最该写的一条** |
| **RAG / KG** | 检索中医文献或结构化知识图谱 | ZhongYan：31 实体类 / 29 关系类 / 5 属性类，专家在环，自称 ≥94.5% 准确 —— **已核实** |

**我们的位置：只做 SFT 一段（LoRA），没有 CPT、没有 RL、没有 RAG/KG。**
这不是短板要遮，而是论文的**卖点要正着写**：在只有一段 SFT、13.6 万条数据、单次 1 epoch 的条件下，做到 MTCMB 10 集横评三档口径全部第一。工作量堆在"每条数据被检查过几遍"，不是堆在阶段数量上。

### 轴三：按**底座族**分

底座差异会直接污染横向比较，综述里点一句能省很多口水：

| 底座族 | 代表 |
|---|---|
| Qwen 系 | BianCang（Qwen2/2.5）、ShizhenGPT-32B（Qwen2）、Fu-TCM-27B（Qwen3.5）、ZhongYan（Qwen3-14B）、**我们（Qwen3.6-35B-A3B MoE）** |
| Yi 系 | HuatuoGPT2-34B、BigDataTCM-34B |
| LLaMA / Ziya / BLOOM 等 | Zhongjing-LLaMA、PULSE（BLOOM） |
| 自研医疗底座 | Baichuan-M1 |

> **我们实测的一条硬证据可以直接支撑这一轴**：Fu-TCM-27B（Qwen3.5-27B 底座）60.21，低于我们**未经训练的裸基座** 68.53 八分；而 Xinghe1.2-9B（小三倍）63.38 又打赢了 Fu-TCM-27B。**底座族和参数量都不单调决定中医任务表现。**

## 二、评测基准的版图（综述里通常缺的一段）

中医大模型的评测集分两类，这个区分对我们的立论很关键：

| 类型 | 例子 | 问题 |
|---|---|---|
| **公开基准** | **MTCMB**（12 集 / 7,100 题，Zenodo 归档）、TCMBench `[待核]`、CMB / CMExam 的中医子集 `[待核]` | 可复现、可比；但金标与评分管道本身可能有缺陷（这正是我们的命题） |
| **自建未公开基准** | ZhongYan 的 ZhongYiBench（客观 5,242 + 主观 232，**未公开**）—— 已核实 | 外部**无法复现其任何一个数**。这是可以温和指出的方法学问题 |

**我们选 MTCMB 而不是自建的理由**（写进 Methods 的动机段）：
1. 公开、可复现、有 Zenodo DOI 与冻结题单；
2. 五维覆盖，不是只有选择题；
3. **正因为它公开，我们才能把"金标错 / 评分管道错"逐条摆出来** —— 换成自建集，这套勘误没有第三方能验证。

## 三、数据版图：中医大模型都在用什么数据

| 数据类型 | 常见来源 | 谁在用 | 我们用没用 |
|---|---|---|---|
| 中医古籍 | 1500+ 部古籍全文 | ZhongYan（CPT 2.4B token） | 少量（911 条，本草纲目/神农本草经/千金翼方等） |
| 规划教材 | 十三五 / 十四五规划教材 | 广泛 | **主力：十四五 35 部，75,600 条（55.67%）** |
| 配套习题集 / 考试题库 | 执业医师、主治医师题库 | 广泛（**也是泄漏高发区**） | 十四五配套 18 册，24,645 条（18.15%） |
| 《中国药典》 | 2020 年版一部 | 部分 | 17,684 条（13.02%） |
| 真实电子病历 EHR | 医院 HIS 导出，需 IRB | ZhongYan（45k 条，3 个伦理批号） | 无院内数据；用公开的 **TCM-SD** 10,764 条 |
| 中医标准术语 | 国标《中医临床诊疗术语·证候》 | 少见 | **1,969 条 —— 这是块少有人开采的干净证据源** |
| 期刊论文 / 临床指南 | CNKI、指南汇编 | ZhongYan（300+ 论文、120+ 指南） | 无 |
| 名医医案 | 医案汇编 | 广泛 | **实测语料太脏，未采用**（四道闸都过的样本仍 5/8 带 OCR 坏字） |
| 合成数据 | LLM 生成问答 / CoT 蒸馏 | 广泛，**质控普遍不写** | 有，但全部走"证据表 → 问法 → 硬闸"，判废率 8.9%，废因逐条留档 |

> **这一张表就是江老师说的第（3）条贡献的骨架**："对比起很多量很大但质量无法保证的数据而言，我们的数据量没那么大但效果显著"。左边这一列是"大家都在用什么"，我们在**每一格里都能说出自己那一格是怎么验的**（见 04 文件），这是别人写不出来的部分。

## 五、一条必须写进 Related Work 的引文锚

ZhongYan（IEEE JBHI，北大软微+计算机+中国中医科学院，10 作者，国家重点研发 2023YFC3502900）在 §V-C-4 写道：他们试过在答错的题上做迭代微调，但**收益有限**，归因于"上下文不足或**金标本身有歧义（ambiguous ground truth）**"，然后把解法留给了未来工作。

**这正是我们整篇文章的命题** —— 他们一段话，我们一篇论文。这是最好的引文锚：既证明这个问题是领域内公认存在的，又说明还没有人系统地做过。

（同时也是催命符：这个命题已经有人踩到边了，方法稿要抢时间。）
