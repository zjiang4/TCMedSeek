### 为什么 LoRA 目标必须写成正则 —— 这是可写进论文的一个实现要点

35B-A3B 的实际结构（我们用 `scan_lin.py` 扫出来的）：**40 层里只有 10 层是 `self_attn`（q/k/v/o_proj），另 30 层是 `linear_attn`（in_proj_qkv / out_proj / in_proj_a/b/z / conv1d）**，名字完全不同。

- 若照惯例给 `target_modules=["q_proj","k_proj",...]`，**只会覆盖 1/4 的层**。
- 256 个 routed expert 在 `Qwen3_5MoeExperts` 里是融合参数、不是 `nn.Linear`，peft 碰不到（实测命中 0）；`mlp.gate`(router) 与 `shared_expert_gate` 一律不挂。
- 最终覆盖 = 10×4 + 30×2 + 40×3 = **220 个模块，40/40 层**。

实际用的正则（`run_v79.sh` 里的 `LORA_TARGETS_REGEX`）：

```
^model\.layers\.[0-9]+\.(self_attn\.(q|k|v|o)_proj|linear_attn\.(in_proj_qkv|out_proj)|mlp\.shared_expert\.(gate|up|down)_proj)$
```

### 合并验收（证明 adapter 真的合进去了，也证明没误伤）

| 检查 | 结果 |
|---|---|
| 命中模块数 | 220 / 220（少一个即断言失败） |
| 索引与实际权重 | 需要 1,045，实际 1,045，缺 0 多 0 |
| 已合并模块（q_proj / in_proj_qkv） | 与基座逐位**不同**，相对改动 9.9% / 9.3% |
| 未合并模块（layernorm / mlp.experts） | 与基座逐位**完全相同** |

最后一行是关键：MoE 的 256 个 routed expert 与 router 一律没挂 LoRA，合并后必须与基座逐位一致 —— 这一条同时排掉了「合并成了原始基座」和「误改了不该改的层」两种失败。

### 逐条来源回溯 —— 这一段建议单独写一小节

我们做了**逐条**来源回溯：每条样本落到「语料 + 册 + 行号」，未定条数从 40,263（29.7%）降到 **166 条（0.12%）**。全量跑一遍 4 分 36 秒。

| 确定方式 | train | 说明 |
|---|---:|---|
| 声明 | 71,520 | 建库时 `meta.source` 就写了 |
| **回溯** | **59,616** | 本次逐条匹配原始语料补上的 |
| 声明·无上游原文 | 3,342 | 通用对齐 / 人工撰写 |
| 按构造 | 716 | think 自然段落、方法卡，本来就没有上游原文 |
| 声明(trust_src) | 437 | source 未写但 trust_src 写明了语料 |
| 未定 | 166 | 六条路都判不出 |

**判定顺序写死为「建库声明优先于回溯」**：声明是过程真值，回溯是外部证据。两者一致率 86.2%（药典 99% / 国标 97% / TCM-SD 96% / 习题集 87% / 教材 71%）。

**三个先在样例上暴露、修完才敢上全量的判据缺陷**（方法学上值得写）：

1. 题面模板会命中习题集自身的分节指令（"以下是一道考题，有A、B、C、D、E五个备选答案"），整批一律命中 41 字 → 修法：≥300 条不同样本题面里出现的 12-gram 判为模板并遮蔽。
2. `data/jiaocaitxt/txt` 里有 27 本与十四五教材同名但属旧版次，混进古籍会张冠李戴 → 单列"教材(旧版次)"，版次单独标。
3. **纯比匹配长度会把教材/药典成片判给习题集** —— 因为习题集正文复述教材与药典原文 → 用 74,997 条已声明 source 的行当标注集校准规则：匹配长度在最长值 25 字内视为相当，按"谁是原产地"取（药典/国标 > 教材 > 古籍 > 习题集）。总一致率 80.6% → 86.2%。

**6,860 条 ambiguous 只给候选册清单、不硬判** —— 内容确实同时存在于多册，硬判会造出假来源。

**工具**：`0728/tools_prov/`（prov_engine / prov_run / prov_retrieve / prov_calib / prov_write / prov_summary 六个脚本）；标注版数据 `deliver_v7_9/01_sft数据集/tcm_sft_v7_9_{train,val}_prov.jsonl`。

| 通道 | 查什么 | 逼出它的事故 |

| **F 40 字滑窗** | 评测集全文（**含 answer 字段**）建 70 万窗索引，训练侧逐位置查 | 旧闸只查题面不查答案 —— 答案里抄了金标同样是泄漏 |

D/E/F 是 v7.9 补的。**补之前，旧闸和 `leakgate65` 在同一份数据上都报 0，补完抓出 64 条真泄漏。**

> **本项目最该写进论文的一条经验：闸门报 0，可能是数据干净，也可能是闸门有盲区。所以"报 0"必须有第二个独立实现复核，且每发现一次漏网就补一条通道、永不删除。**

### 5.3 三次真实事故（Results 里的实证材料）

**事故一：片段闸完全漏检 251 道原题。** ED-A/ED-B 共 6,000 道选择题与十四五习题集同源，同一道题两边常差几个字（OCR、排版、加"单选题"前缀、"是"→"是什么"），30 字连续片段对不上，**但它就是同一道题**。v5.0 存量里 251 条 benchmark 原题被旧闸全部放过。修法：改用归一后 3-gram Jaccard 的题干闸。

**事故二：把症状打乱顺序，不是消除泄漏，是规避检测。** 早期修复脚本遇到泄漏时"把症状短句重新排序"，理由是"顺序不承载医学信息"。病例还是同一个病例，模型照样见过测试集内容，只是顺序敏感的 n-gram 判据看不见了。补一道**字符多重集 Jaccard**（对重排免疫）抓出 110 条。**此类样本一律删除，明令不得再用重排"修复"。**

**事故三：三个机制盲区。** 三版数据在"零泄漏"认证下交付，最终产物里含 248 条逐字原题。

**泄漏清理台账**

| 阶段 | 删除 | 触发通道 |
|---|---:|---|
| v5.0 存量 | 251 | 题干闸（片段闸全漏） |
| v5.1 加固 | 167 | 长题干阈值降至 0.45 + 词袋闸（含被重排规避的 110 条） |
| v7.7 | 7 | 包含度阈值 40 字 → 12 字 |
| v7.9 | 64 | 新增 D/E/F 三通道 |

### 5.4 阈值是定标出来的，不是拍的

题干闸阈值按 0.30~0.75 全区间逐条核对后定：

- **长题干（≥25 字，病案类）→ 0.45**。J 0.45~0.55 已大量是同一病例的改写（正文逐字一致，只换年龄与问法）。
- **短题干（<25 字）→ 0.75**。短题干的 3-gram 里句式占比高，Jaccard 天然虚高：「降香具有的功效是」vs「木香具有的功效是」J=0.71，**是不同题**。在短题干上压低阈值，**误删的恰恰是最有价值的辨异题**。

同样的定标纪律出现在 D 通道：题干相似度一开始设 0.5，把 B 型题共用选项池成片误判，提到 0.8 后干净。

### 5.5 边界：删什么、不删什么

1. **删同题，不删同知识点。** ED-A/ED-B 与十四五习题集出自同一考试体系，知识点必然重叠 —— 后者删了等于不许学这门课。v7.9 删 64 条后做覆盖复查：奇经八脉 203 处、津液 1,978 处、藿香正气散 298 处、苓桂术甘汤 387 处、黄连温胆汤 556 处，**知识点一条没丢，丢的只是那道题本身**。
2. **few-shot 示例块不给豁免。** 复刻评测 prompt 时示例块一律用自家病案现搭，不照抄官方示例。
3. **误删也要留证。** v7.9 显式保留 5 条"同选项池但确为不同问题"的样本，逐条写明理由并在闸门里登记例外。

## 六、"有效合成"具体是怎么做的

江老师说的"数据量没那么大但有效合成"，落到操作上是这一条设计原则：

> **先有可核验的事实，再有问法。顺序不能反。** 事实由证据表定死，生成侧（LLM 或人）只负责把它写成自然的一问一答；回收时任一硬闸不过，**整条判废，不做"顺手修补"**。

### 6.1 三步流程

**第一步，先建证据表**（`r64_records.py`）。每条记录 = 一份来自可信表的原始事实 + **允许出现的实体白名单**。可信表都不是 OCR 教材正文：

| 可信表 | 条数 | 内容 |
|---|---:|---|
| `fangji_final.json` | 379 首 | 识图抄录 + 交叉校验（组成/功用/主治/用法/出处） |
| `formula_table.json` | 384 首 | 方名 → 组成串 |
| `pprc_items2.json` | 2,097 条 | 《中国药典》2020 一部 |
| `_gb_zhenghou.json` | 2,012 条 | 国标证候 |
| `op_zhengzhi.jsonl` | 751 条 | 教材证治条目 —— **有串段风险，只当配方对的来源用，不单独出题** |

**第二步，生成侧只写问法。** system prompt 明写"答案必须只用给定材料里的事实"，并禁止出现"教材中""原文中""根据材料"这类字眼（学生问的是知识，不是文献）。每条随机抽一个"问法角度"（每包 6~12 种），避免整包塌成一种问法。

**第三步，回收硬闸**（`check()`，任一不过整条判废）：

- 过短/过长、带花括号/代码块/列表符号 → 废
- 命中禁用问法（"下列关于""以下说法""试述""教材中是如何论述"）→ 废
- 答案里出现文献口吻（教材/原文/材料/国标）→ 废
- 答案是"材料里没有""无法确定"这类非答案 → 废
- **问题里没点出主体名** → 废（防"家里老人抓来吃行不行"这种指代不明的空问）
- **合方组成里混进不属于两方的药** → 废；**该写全组成却漏了药** → 废
- **证素答漏规则证人的词** → 废
- **剂量不在药典原文里** → 废（"凭空给了剂量"单独一条废因）
- 有毒性标注却没点出毒性 → 废
- **问法骨架密度封顶**：同一骨架在包内不得超过 12%

**实测判废率 8.9%（331 / 3,730）**，废因逐条留档：

| 包 | 收 | 判废 | 主要废因 |
|---|---:|---:|---|
| P1 合方 | 722 | 78 | 文献口吻 32 / 该写全组成却漏了 26 / 问句重复 18 |
| P3 证素 | 483 | 110 | **问法骨架超密度封顶 75** / 没点出主体名 32 |
| P4 证候 | 700 | 94 | 没点出主体名 74 / 过短 17 |
| P6 药物 | 694 | 5 | **剂量不在药典原文里 3** |
| P7 安全 | 98 | 20 | 密度封顶 17 / 剂量 3 |
| 其余 | 702 | 24 | |

> P7 第一版有 26% 都是"家里老人自己抓 X 来吃行不行"，换个药名重复 30 遍 —— 密度封顶就是为这个加的。

### 6.2 错题卡：先找证人，找不到就不造

针对实测错题造的卡片（2,257 张）风险更大 —— 很容易写成"复述题干"，那等于把测试题写进训练集。

| 机制 | 做法 |
|---|---|
| **先找独立原文证人** | 证人库 = 教材 txt_clean 35 本 + 国标证候 + 药典。**找不到证人的题不造卡**（教训：没有独立原文那一路的错题卡，40% 会被泄漏闸删掉 —— 删除率本身就是判据） |
| 不许复述题干 | 卡片问句与原题干的最长公共子串 **≥10 字即判泄漏**，废 |
| 金标必须真出现在答案里 | 否则废（教训：只比金标前 4 字，放过了"教模型错答"的反向卡） |
| 鉴别卡必须提到误选项 | 否则等于没教分界 |
| **不许越过证人发挥** | 出现"虽未直接提及""据此推断""可推测"等对冲措辞 → 废 |
| 与证人原文实词重合 | 答案与证人原文 4-gram 重合 <3 → 判"脱离证人原文"，废 |
| "已教仍错"不收知识卡 | 已经教过还错，缺的是与误选项的**分界**，再加一遍知识量无效 |
| **盲重答做第二证人** | 看着金标那一审会替模型辩护；改用不看金标的盲答复核，**79 条"金标存疑"被推翻 29 条** |

### 6.3 密度扫查的靶子是什么（一个反直觉的点）

**靶子不是"答案重复"** —— 闭集任务答案本来就那几个，没有分辨力。靶子是**同一种问法被换个实体重复了 N 遍**。所以要先把实体名、数字、书名号内容**掩掉**，再看剩下的骨架有多集中。

实测（掩掉实体名后的问法骨架，门槛 5%）：

| 批次 | 条数 | 骨架种数 | 最大占比 |
|---|---:|---:|---:|
| v6.4 LLM 包 | 3,246 | 2,389 | 1.2% |
| v6.4 手写包 | 1,564 | 1,038 | 1.2% |
| 通用集 | 1,027 | 1,027 | 0.1% |

## 七、三条贯穿始终的纪律（适合做 Methods 的收尾段）

**一、判据先在样例上验，再上全量。** 报 0 和报爆表都先怀疑判据。逐条来源回溯时，样例就暴露了三个判据缺陷，修完才上全量。

**二、宁可留空，不给假标签。** 兼证证据不足 → 降级；找不到独立证人 → 不造卡；来源判不出唯一 → 输出候选清单标 `ambiguous`；同义/存疑判不准 → 一律删。

**三、报 0 必须有第二个独立实现复核。** `q4_gates_v79.py` 与 `leakgate65.py` 是两套独立实现，都跑，都要 0。

## 九、已知局限（引用本文件前必读，Limitations 一节的原料）

1. **未定 166 条（0.12%）**，全是医古文/古汉语类知识问答，改写幅度大到没有可匹配的原文片段。
2. **教材侧 7,369 条判为教材但册名未定**，多为跨册合成与识图抄录批次。
3. **回溯与建库声明一致率 86.2%**，教材那一列只有 71%（方剂学等几本走"PDF 识图抄录"，内容不在 txt 语料里）。报告采信建库声明，回溯只用于填空与交叉核。
4. **6,860 条 ambiguous** 只给候选册清单，是有意为之。
5. **约三分之二源材料是扫描件**，走 OCR 进入语料。有文本层的 14 本干净，走 OCR 的 21 本存在整批丢字。已量化的结论是：**含丢字药的题错误率 8.8%，低于对照组 9.8% —— 丢字不是答错的主因，残留坏字才是**（v7.9 已修 83 处）。
6. **TCMeEE 的 Disease Name 仍是 658/658 填「无」**（金标 69/100）。训练侧 658 条医案含西医诊断线索的是 0 条，补这一项只能往医案里编细节。**唯一显式保留的口子，已知、已量化。**
7. **单一来源依赖**：用药安全 91.1% 来自药典、辨证辨病 67.0% 来自 TCM-SD、文献抽取 86.4% 来自教材内引文。药典 OCR 的数字位错误会直接变成安全事故 —— SE-A 实测中"毒性药剂量往大里错"就是这条链路。
8. **train/val 组泄漏**：同一部文献、同一方剂的不同问题会分处两侧。只影响自用 val 的绝对值，不影响 benchmark 分数 —— 所以口径是**判涨跌只认固定评测切片，不看 val loss**。
9. **benchmark 与习题集的题库同源性无法消除**：同出一个考试体系，知识点必然重叠。我们删同题，不删同知识点。
10. **医案语料未采用**：四道闸都过的样本仍 5/8 带 OCR 坏字，判定为太脏不能用。
